## Этапы и контрольные точки

1. Основа: 001–003, 005–006. Рабочий Cmd, аудит, manifest и воспроизводимый Classic baseline.
2. Дизайн: 004 и 008. Новый icon set с возможными 2x assets при прежнем физическом/CSS размере и разрешённая палитра. После показа полного набора получить явное одобрение пользователя; до него TASK-013 заблокирована.
3. Тема: 007–013. Сначала неизменённый child, затем color layer, затем новые icons. Так можно определить источник регрессии.
4. Доказательства: 014–016. Геометрия, поведение, визуальные сравнения и build matrix.
5. Поставка: 017. Документация и фактический отчёт. 018 — отдельное необязательное расширение на 7.9.

Карточки выполнять по зависимостям. Статусы TODO → IN_PROGRESS → DONE, BLOCKED с причиной; TASK-004 перед DONE обязательно проходит WAITING_USER_APPROVAL. Не отмечать задачи DONE по наличию плана. Фактическое состояние работ отражено в карточках; готовность темы требует итоговой приёмки.

## Правило запуска

Начать с TASK-001. После него выполнить аудит/каталогизацию, создать новый набор значков в TASK-004 и получить Classic baseline до изменения темы. Не обновлять golden для сокрытия дефекта. Реалистичную оценку пересчитать после аудита: 53–90 часов из PDF не включает явно расширенную работу по новому icon set и не является обещанием срока.
