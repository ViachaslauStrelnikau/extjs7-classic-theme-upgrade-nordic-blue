# Nordic Blue для Ext JS Classic: требования и план

## Контекст беседы

В исходной беседе «Исследование тем Ext JS» пользователь сначала запросил три варианта темы в той же конфигурации, что и приложенный Classic пример. Из вариантов выбран **Nordic Blue**. Затем пользователь попросил поправить вылезающий текст и неровно стоящие стрелки, сохранив совместимость с Classic. Скриншот исходного Classic примера сохранён в docs/reference/classic-baseline.png (1032 × 1220 пикселя).

Полный технический проект теперь доступен в этой папке в PDF (32 страницы) и прочитан. Инструкции по его реализации: [руководство агента](nordic-blue-agent-guide.md) и [план с задачами](plans/nordic-blue/README.md). Уточнения пользователя, особенно новый набор стандартных значков, имеют приоритет над рекомендациями PDF.

## Цель

Подготовить сменную тему Nordic Blue для существующих приложений Ext JS Classic. Приложение должно работать с ней так же, как с базовой theme-classic: компоненты, конфигурации и пользовательское поведение остаются прежними; тема меняет визуальное оформление.

**Целевая версия — Ext JS 7.7.0, Classic toolkit.** В добавленном SDK подтверждена сборка 7.7.0.31 (release 7.7.0) по version.properties. Ссылка на Ext JS 7.9 ниже нужна для визуального ориентира и сверки, а не для смены целевой версии.

## Архитектурные решения

1. Использовать **Sencha Cmd** и отдельный пакет типа theme для Classic toolkit.
2. Пакет должен расширять установленный пакет **theme-classic**. В SDK 7.7.0.31 он найден в classic/theme-classic/package.json; поле sencha.name равно theme-classic, toolkit равно classic, а ext-theme-classic указан как alternateName. TestApp/app.json использует этот alternateName. Создавать новую тему средствами Cmd и проверить поля type, toolkit и extend в сгенерированном package.json.
3. Не менять код приложения ради вида темы. Приложение может только подключить пакет и выбрать его как тему в конфигурации тестовой сборки.
4. **Обновить стандартные значки Nordic Blue.** Сначала зафиксировать исходный Classic baseline и каталог assets, затем создать новый набор (TASK-003/004) и подключить его (TASK-013). Сохранять размеры image/display box, sprite grid/offsets, состояния, hit areas и behavior. Наследовать незаменённые ресурсы. Не менять DOM/типографику/геометрию ради новой иконки. Утверждение PDF о пустых resources v1 заменено этим прямым указанием пользователя.
5. Визуально менять палитру и оформление поверхностей в рамках выбранного Nordic Blue. Сохранять размеры, позиции, отступы и шрифтовые метрики Classic: bounds, ширину и высоту, padding, line-height, семейство/размер/начертание шрифта и letter spacing.
6. Сохранить все состояния и поведение компонентов: hover, pressed, focus, disabled, раскрытие/сворачивание, навигацию с клавиатуры и реакции на события.
7. Вылезающий текст и кривые стрелки исправлять по источнику проблемы: проверить шрифт и его метрики, line-height, padding, выравнивание, glyph/sprite и CSS. Не исправлять визуальный дефект незаметным изменением размеров компонента.

## Референсы

- [Ext JS 7.9 Classic themes example](https://examples.sencha.com/extjs/7.9.0/examples/classic/themes/) — визуальный ориентир из исходной беседы.
- [Официальное руководство по темам Ext JS 7.7](https://docs.sencha.com/extjs/7.7.0/guides/core_concepts/theming.html) — генерация темы, наследование, переменные, JavaScript overrides и изображения.
- [Официальное руководство Sencha Cmd 7.7 по пакетам](https://docs.sencha.com/cmd/7.7.0/guides/cmd_packages/cmd_creating_packages.html) — структура, наследование и сборка пакета.

В руководстве 7.7 сказано, что Classic theme packages наследуют родительскую тему, включая необходимые image assets; одноимённые файлы в resources/images/ служат для переопределения. Для темы Classic указано имя пакета theme-classic. При этом изображение из исходной беседы — историческая визуальная опора, а не подтверждённый снимок Ext JS 7.7. Снимите отдельный базовый скриншот на фактически установленной версии 7.7.

## Проверка геометрии и внешнего вида

Сравнивать базовую Classic тему и Nordic Blue в одном тестовом Classic приложении, на одном SDK, с одинаковыми данными и состояниями, в том же браузере, масштабе, разрешении и масштабе экрана.

Для одинаковой выборки компонентов проверить:

- координаты и прямоугольники компонентов и их дочерних частей;
- ширину/высоту, min/max размеры, отступы и размеры строк;
- метрики шрифтов, переносы и отсутствие обрезанного/вылезающего текста;
- положение стрелок, кнопок сворачивания, маркеров, caret и других glyph/sprite;
- иконки и ресурсы Classic, их URL/имя, размер и отображение;
- состояния hover, pressed, focus, disabled и раскрытые/свёрнутые состояния;
- клики, ввод, навигацию с клавиатуры и остальные действия в тестовом наборе.

Сравнение выполнять и по геометрическим измерениям, и по скриншотам. Допускаются только различия, вызванные цветом и выбранным оформлением Nordic Blue; смещение или изменение размеров, метрик шрифта и поведения считается дефектом. Для первичной визуальной проверки используйте сохранённый Classic скриншот, но итоговый baseline должен быть снят на том же SDK и в том же тестовом приложении, что и новая тема.

## Дорожная карта

1. **Инвентаризация SDK и инструментов.** Найти установленный Ext JS SDK, проверить версию по файлам SDK/метаданным, убедиться в наличии Classic и theme-classic. Проверить sencha -v, Java и совместимость Cmd с Ext JS 7.7. Не скачивать и не обновлять SDK без отдельной необходимости.
2. **Рабочая структура.** Создать/инициализировать Sencha workspace, затем сгенерировать отдельный Classic theme package средствами найденного Cmd. Проверить пакетную конфигурацию и наследование theme-classic.
3. **Базовое тестовое приложение.** На Ext JS 7.7 собрать Classic-пример с тем же набором компонентов, что в референсе. Снять базовые скриншоты и измерения.
4. **Nordic Blue без изменения геометрии.** Перенести палитру и визуальные решения выбранного варианта. Сохранить исходный Classic baseline; новые icons интегрировать отдельной задачей после color layer. Исправить переполнение текста и выравнивание стрелок, не затрагивая контракт размеров и поведения.
5. **Сравнение.** Снять Nordic Blue в тех же условиях, сопоставить размеры/координаты и скриншоты, пройтись по каждому компоненту и состоянию. Все отличия значков объяснить их источником и записью в журнале решений.
6. **Сборка и проверка.** Выполнить реальную сборку Cmd-пакета и тестового приложения на Ext JS 7.7, затем проверить тему в браузере и пройти интерактивные сценарии.
7. **Отчёт.** Зафиксировать версии SDK и Cmd, команды сборки, браузер, проверенные сценарии, результаты геометрического/визуального сравнения и оставшиеся расхождения.

## Условие готовности

Тема не считается готовой по макету, исходникам Sass или успешному созданию пакета. Готовность можно заявить только после успешной сборки Sencha Cmd и проверки собранной темы в тестовом Classic приложении с геометрическим, визуальным и функциональным сравнением с theme-classic. В отчёте указывать подтверждённые результаты, а не планируемые проверки.

## Проверенное окружение

В добавленном SDK ext-7.7.0.31/version.properties указаны version.full=7.7.0.31 и version.release=7.7.0. Файл TestApp/ext/version.properties сообщает ту же сборку. В classic/theme-classic/package.json подтверждены имя пакета theme-classic и Classic toolkit; ext-theme-classic является его alternateName. В TestApp/app.json выбран Classic toolkit и эта тема.

В package.json установлена зависимость @sencha/cmd-windows ^7.7.0; метаданные установленного пакета сообщают 7.7.0.36. Локальный вызов бинарного файла с параметром -v не завершился при проверке. PATH также содержит старый Cmd из C:\Users\Damned\bin\Sencha\Cmd\4.0.5.87; его вызов sencha version также был остановлен без результата. Перед сборкой проверьте запуск Cmd и сборку тестового приложения. SDK и TestApp уже находятся в проекте; изучите их перед изменениями и не редактируйте файлы SDK.

Полная декомпозиция: docs/plans/nordic-blue/README.md. Обязательный результат включает Nordic icon set; метрики и поведение Classic сохраняются. При расхождении старых заметок руководствоваться актуальными указаниями пользователя и docs/nordic-blue-agent-guide.md.

## Уточнение пользователя: плотность и одобрение значков

Повысить плотность пикселей значков, если это безопасно поддерживается SDK/Cmd, сохранив физический размер в интерфейсе: неизменны CSS dimensions/rects, hit area и logical sprite offsets. Например, bitmap 32×32 при DPR=2 отображается в прежнем box 16×16 CSS px. Подготовить качественный 1x fallback и проверить DPR=1/2 отдельно. После создания полного набора показать превью всех состояний и получить явное одобрение пользователя конкретной версии до интеграции TASK-013. TASK-004 до этого имеет статус WAITING_USER_APPROVAL. Подробные правила — в руководстве агента.
